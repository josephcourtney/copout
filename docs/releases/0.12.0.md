# Copout 0.12.0

Copout 0.12.0 improves the fidelity and readability of captured terminal output, while retaining the selector-first CLI introduced in 0.11.0.

## Highlights

- **Structured schema v9:** separate the size of Atuin's retrieved rendered snapshot (`captured_bytes`) from the size of Copout's normalized presentation (`presented_bytes`). Preserve upstream exit-capture signals and distinguish `unknown`, `incomplete`, and `unavailable` capture completeness.
- **Readable terminal snapshots:** normalize ANSI styling and common cursor, carriage-return, backspace, and erase-line controls consistently across XML, JSON, and Markdown.
- **More useful large captures:** raise presentation limits to 256 KiB per run and 1 MiB per selection, with explicit omission metadata. The 2,400-line / approximately 201 KiB regression probe now fits without Copout-side truncation.
- **Improved picker:** compact, bounded-width inline selection UI with height adapted to the number of recent commands.
- **Diagnostics and safeguards:** reproducible Kitty/Atuin/Copout comparisons, isolated Atuin test-session verification, historical Git-context provenance tests, a Typer compatibility matrix, and a paired context-enrichment benchmark.

## Important behavior

Atuin provides a **rendered, recent terminal snapshot**, not a guaranteed full PTY transcript. An upstream `truncated: false` does not establish completeness. Copout now reports ordinary snapshot completeness as `unknown` and reports Copout-side presentation omissions separately.

The structured record remains the universal `runs` envelope introduced in schema v8; integrations consuming detailed output metadata should accommodate schema v9.

## Requirements

- Python 3.13 or newer
- Atuin 18.23.x; daemon and pty-proxy are required to retrieve recent command output
- Clipboard support through `pbcopy` (macOS), `wl-copy` (Wayland), or `xclip`/`xsel` (X11)
